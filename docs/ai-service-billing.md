# OpenAI assistant with 30% usage markup

The new **Marketplace > AI assistant · usage billing** service sends independent text messages to the OpenAI Responses API using the existing encrypted API key. It has no tools, attached files, automatic access to records, conversation memory, or automatic paid retries. This is an API service, not a resale of a ChatGPT subscription.

## Price calculation

Provider cost = `(uncached input tokens × input rate + cached input tokens × cached rate + output tokens × output rate) / 1,000,000`.

Retail cost = **provider cost × 1.30**, rounded **up once to USD cents per request**. This is a 30% markup on cost, not a 30% gross margin. For example, $1.00 provider cost becomes $1.30; very small charges round up to one cent. Store the exact decimal cost, pre-rounding retail cost, token counts, frozen rates and final cents for each settled request.

Rates are administrator-verified **standard service-tier token prices**, not live imported invoices. Configure the exact project/model rates, including applicable surcharges or account discounts. Default input/cached/output fields are $2/$0.50/$8 per million, matching the published GPT-4.1 standard rates at review; the model is blank and the service is disabled until an administrator verifies the applicable rate card. Other models require their own rates. Model access and retirement remain provider-controlled. Sources: https://developers.openai.com/api/docs/models/gpt-4.1 and https://developers.openai.com/api/docs/pricing . Cached usage reference: https://developers.openai.com/api/docs/guides/prompt-caching . Do not use this service for models with separate cache-write charges; those responses are flagged for reconciliation.

Users explicitly consent to message sharing and a maximum USD balance reservation. The maximum uses a conservative byte-based plain-text input bound plus overhead and the configured output-token cap. If balance is insufficient, no provider call is sent; users add funds through existing wallet controls. After the provider returns valid usage, deduct actual retail cost and release the unused reservation. Provider-billed incomplete responses still cost money. The provider usage/model must fit the approved bound; otherwise retain the reservation for review rather than overcharge.

## Financial safeguards

- Request IDs are unique per owner/workspace; repeated requests return the stored result or current reservation without another provider call.
- Prompt changes under the same request ID are rejected. Price changes require a new quote.
- Quotes do not debit funds; holds and settled billing survive browser disconnects.
- Unknown transport/provider outcomes, missing usage, and unrecognized costs enter **reconcile**. They never automatically retry or silently invent a charge.
- Super admins can refund held requests after checking the provider outcome, with an audited reason. Reservations left by a crashed process become manually refundable after ten minutes. A refunded request ID cannot be used for another paid call. A refund absorbs any provider cost at the platform's expense; it does not refund the provider invoice.
- Wallet holds reduce withdrawable allocation; released/refunded portions restore the corresponding held allocation without exceeding the wallet balance.
- Prompts and answers are encrypted with the existing persistent encryption key. Ordinary users see only their own workspace usage; admin tables show financial metadata only.
- Authentication, CSRF checks, tenant status, role checks, per-user daily request limits and output limits apply. Super admins using the paid assistant also fund their own wallet; there is no hidden billing exemption.

## Deployment and controls

```bash
cd /opt/dobhrap-watchdog-source
git pull --ff-only origin main
ansible-playbook -i 'dobhrap,' -c local ansible/ai-service-oob.yml
```

Then open **Super admin > AI API & 30% usage billing > Manage AI service pricing**. Save an exact model ID, verified input/cached/output rates, output cap and daily request cap, then enable the service. Provider credentials stay in **Provider provisioning & keys**; no new credential is generated by this release. UI settings are revision-checked and changes affect new requests only.

This billing applies to the **new text assistant**. Existing Tax Analyst document-extraction credits, Tax Preparation AI review, support automation and other hosted applications retain their established billing. They are not silently charged both credit prices and cost-plus prices. Applying metered billing to those services requires their own quote, usage and settlement integration. Cross-domain shared-key provisioning is outside this repository.
