# All platform users

Super administrators open **Platform → All platform users** to search registered accounts across every personal and business workspace. Search matches email, display name or workspace, with active/suspended/deleted filters and 100 accounts per page. Results show role, workspace identity/status and account status, never password hashes or API secrets. Profile editing includes phone, job title, address and biography; optional matching new-password fields change the login password. Changing a verified phone clears its verified status. Workspace administrators cannot access this platform-wide API.

Select **Manage user** to edit display name, email or role, suspend/reactivate a user, or permanently remove the user. All mutations require the acting super administrator's current password and the displayed record revision. Password attempts are throttled. Email collisions and stale writes are rejected. Roles cannot grant a super administrator outside the platform workspace. An administrator cannot suspend/delete their own login, and the last active super administrator cannot be demoted or deactivated.

Changes revoke the affected user's sessions and invalidate password-reset links. Suspended/deleted accounts cannot sign in, reuse existing sessions or finish password recovery. Suspension cancels queued outgoing email and pauses managed provisioning for that user. Reactivation restores platform access; paused provisioning remains subject to its existing Retry provisioning controls. Editing a platform email does not automatically rename a remote SIP account or mailbox.

**Permanently delete user** requires typing the current target email. It immediately revokes the login and queues retryable removal of the physical user row, profile, credentials, sessions, reset links and user-owned live-platform records, including private tax documents, wallet records, managed service credentials and communications. Shared workspace records and other users’ data remain. Active unresolved provider work may block or delay removal; pending deletion status is visible. Previously disabled/tombstoned logins can also be permanently removed. Deletion cannot be undone from this screen. Existing independent SIP/mail credentials are not revoked remotely; use their provider administration too. Already running external operations may finish and are not silently retried or reversed.

The shared `users` table adds `account_status`, `account_revision` and `display_name`; existing users default to active. Database migrations run during normal application startup. `/api/platform/users` supports authenticated GET listing and CSRF-protected POST list/edit/suspend/activate/delete operations. All changes create an audit event containing the acting user, target ID and action. No tenant is moved. Editing and suspension do not adjust balances; permanent deletion erases the user-owned wallet records.

Deploy through the existing `ansible/pull-and-deploy.yml` entry point. The full source archive includes `user_management.py` and `user-management.js`; the trusted GUI deployment source is updated as well. Automated backend tests cover privilege checks, session invalidation, reactivation, stale changes, deletion and last-admin protection. A mobile browser test exercises search, editing, suspension and typed-confirmation deletion using a temporary local database.


## Manually create registered users

Click **Create user** on All platform users. Enter display name, email, matching initial passwords (14–1024 characters), initial active/suspended status and your own current administrator password. Select an existing active workspace and role, or create a new personal/business workspace. A new business requires its name; the first user in either new-workspace type is its workspace administrator. Platform super administrators can only be added to workspace #1. Duplicate emails and inactive or missing workspaces are rejected.

Creation commits the user and phone/email provisioning records together. Passwords are hashed; phone/mail provisioning uses separate managed passwords and waits for configured provider readiness. Initially suspended users cannot sign in and do not provision externally until reactivated/retried. No welcome email is sent by this feature and no paid calling credit is granted. Provide the initial password privately to the intended user; it is not displayed in account listings. The existing password-change page can then be used by the user.

Deletion uses `user_deletions` for retry state and `user_id_sequence` to prevent reuse of an erased identity ID. The existing minute worker resumes pending removals across root and workspace databases. Minimal anonymized audit/security and deletion-job metadata remain. Backups, external SIP/mail accounts, copies downloaded by others and shared company records are not erased by this operation.
