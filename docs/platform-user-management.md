# All platform users

Super administrators open **Platform → All platform users** to search registered accounts across every personal and business workspace. Search matches email, display name or workspace, with active/suspended/deleted filters and 100 accounts per page. Results show role, workspace identity/status and account status, never password hashes or API secrets. Workspace administrators cannot access this platform-wide API.

Select **Manage user** to edit display name, email or role, suspend/reactivate a user, or delete its login identity. All mutations require the acting super administrator's current password and the displayed record revision. Password attempts are throttled. Email collisions and stale writes are rejected. Roles cannot grant a super administrator outside the platform workspace. An administrator cannot suspend/delete their own login, and the last active super administrator cannot be demoted or deactivated.

Changes revoke the affected user's sessions and invalidate password-reset links. Suspended/deleted accounts cannot sign in, reuse existing sessions or finish password recovery. Suspension cancels queued outgoing email and pauses managed provisioning for that user. Reactivation restores platform access; paused provisioning remains subject to its existing Retry provisioning controls. Editing a platform email does not automatically rename a remote SIP account or mailbox.

**Delete user login** requires typing the current target email. It irreversibly replaces the login email with a random tombstone address, removes the display name, replaces password credentials, revokes sessions and marks the row deleted. This is account-login deletion, not destruction of the user's financial, tax, audit or workspace records. Deleted logins cannot be reactivated from this screen. Existing independent SIP/mail credentials are not revoked remotely; use their provider administration too. Already running external operations may finish and are not silently retried or reversed.

The shared `users` table adds `account_status`, `account_revision` and `display_name`; existing users default to active. Database migrations run during normal application startup. `/api/platform/users` supports authenticated GET listing and CSRF-protected POST list/edit/suspend/activate/delete operations. All changes create an audit event containing the acting user, target ID and action. No tenant is moved and balances are not changed by these controls.

Deploy through the existing `ansible/pull-and-deploy.yml` entry point. The full source archive includes `user_management.py` and `user-management.js`; the trusted GUI deployment source is updated as well. Automated backend tests cover privilege checks, session invalidation, reactivation, stale changes, deletion and last-admin protection. A mobile browser test exercises search, editing, suspension and typed-confirmation deletion using a temporary local database.
