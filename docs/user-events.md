# User activity and security log

Super admin opens **Platform → User activity & security log**. It shows timestamp, actor/affected user IDs, workspace, event category, route category, method and response status, with user/status/category/time filters, pagination and JSON export of the displayed page. **View user events** in user management opens that filter. The API is `/api/platform/user-events` and is restricted to active super administrators.

Application API calls are recorded after completion, including successful/failed sign-ins, registration, logout, reads, denied requests, validation/provider errors and administrative actions. User mutations carry create/edit/suspend/activate/delete event names. Client-side navigation, button clicks and form submissions are also recorded as UI categories associated with the current page. UI events are client-reported metadata, not independent proof of a click. Failed anonymous requests have actor 0. Browser events can be lost if a session closes or connectivity fails; database failures are reported to service logs rather than breaking the original request.

Request bodies, query strings, passwords, reset/OTP tokens, API keys, OTP codes, user-entered form values and uploaded document contents are excluded. Access-log query strings are also stripped. External SIP calls, mailbox access outside this application, vendor consoles and OS/device events are not ingested. Background jobs retain their existing audit trail; this screen is not an all-system SIEM. The shared `user_events` table stores structured metadata; it does not mirror all underlying business records or serve as a backup.

The log has no web delete/edit operation. Permanent user removal anonymizes actor/affected-user references in these events and replaces that user's legacy audit text with an anonymized marker. Minimal deletion-job and security metadata remain; other users' audit and shared workspace records are preserved. API events and UI activity do not contain a recoverable user profile after removal.
